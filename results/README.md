# results/ — index

This folder has four separate sets of generated output, tied together by
**`REPORT.md`** (the consolidated narrative report — start there for the
"what does it all mean" version; this file is just the file-by-file map).

## 0. Report + environment

- **`REPORT.md`** — the consolidated report: all four figures, the op-ledger
  table, the six-bucket prove breakdown, and a priority-ordered "bottleneck
  conclusions" section reasoning across all of it.
- **`ENV.md`** — hardware/OS/toolchain the benchmark data was captured on
  (cores, RAM, `perf_event_paranoid`, rustc version, `ezkl` build flags, the
  `halo2_proofs` fork pin) and what it means for interpreting the numbers.

## 1. Stage-level pipeline benchmark (gen-settings → ... → verify)

- **`summary.csv`** — one row per model config, with an `overall_status`
  column (`OK` / `FAILED(<stage>:<reason>)`), logrows/num_rows/lookup fields,
  per-stage wall-time/max-RSS/status, and proof size. **Documented in the
  module docstring of `scripts/bench_stages.py`** (the script that produced
  it) — read that for column meaning, the OK/TIMEOUT/OOM_OR_KILLED status
  semantics, the reps/warm-up methodology, and the `--calibrate-scales`
  option used for the scale sweep below.
- **`seq*_d*_l*/`, `seq32_d64_l1/`, `seq32_d256_l1/`** — one directory per
  model config benchmarked, each holding the actual pipeline artifacts
  (`settings.json`, `model.compiled`, `kzg.srs`, `pk.key`, `vk.key`,
  `witness.json`, `proof.json`) plus `logs/<stage>[.repN|.warmup].log` (full
  `RUST_LOG=debug` output) and `logs/<stage>.metrics.json` (parsed
  wall-time/RSS per attempt). Structure is also documented in
  `scripts/bench_stages.py`'s docstring. `seq32_d64_l1` and `seq32_d256_l1`
  are the pre-rescale "original base" and "OOM-ceiling" configs — see
  `models/README.md` for why those two specifically are still here.
- **`seq8_d16_l1_scale{4,7,10}/`** — the controlled quantization-scale sweep:
  same model as `seq8_d16_l1`, `calibrate-settings --scales N` pinned instead
  of auto-searched. See `REPORT.md` §2 for what this found (row count is
  scale-insensitive here; prove time is flat across 4/7/10, +9% at the
  original unscaled run's scale=13).
- **`figures/`** — the four report figures (`fig_a_prove_vs_seqlen.png`,
  `fig_b_memory_vs_logrows.png`, `fig_c_stage_stacked.png`,
  `fig_d_scale_sweep.png`), generated by `scripts/plot_figures.py` from
  `summary.csv` + `models/MANIFEST.csv`. Rerun that script after any new
  benchmark row to refresh them.

## 2. `prove`-stage flamegraph / hotspot breakdown

- **`PPROF_README.md`** — full explanation: what each run label
  (`seq4_1thread`/`seq4_nthread`/`base_nthread`) means, what each of the six
  category buckets matches, why the multithreaded runs' `other` bucket is
  mostly rayon idle-thread noise, and what every file below is.
- `flamegraph_1thread.svg`, `flamegraph_nthread.svg`, `flamegraph_base_nthread.svg`
- `prove_breakdown.csv`, `prove_breakdown_other_top_symbols.csv`, `prove_breakdown.png`
- `pprof/` — raw `.folded`/`.svg`/`.log` per run (source data behind the CSVs/PNG above)

## 3. Per-operator row/lookup ledger (op-level circuit-layout attribution)

- **`LEDGER_NOTES.md`** — the three-question analysis (matmul vs
  nonlinearity+rescale row share, rescale's share of lookup usage, largest
  lookup table + its operator), plus what the debug log can and can't tell
  you about per-op lookup counts, and exactly where to add real
  instrumentation in `src/circuit/ops/layouts.rs` if you need the latter.
- **`scripts/parse_ledger.py`** — the parser itself; full log-format
  assumptions (including two easy-to-miss layout-repeat quirks it corrects
  for) and category-assignment rules are in its module docstring.
- **`<config>/op_ledger.csv`** — one row per semantic category (matmul, qk,
  av, softmax, gelu, layernorm, rescale, other): total rows, row share %,
  lookup-op-instance count, instance share %. Currently generated for
  `seq8_d16_l1` and `seq32_d64_l1` (the two configs `LEDGER_NOTES.md`
  cross-checks against each other). Rerun `parse_ledger.py <config-dir>` to
  produce it for any other already-benchmarked config.
- **`<config>/op_ledger_raw_nodes.csv`** — the ungrouped per-node data
  `op_ledger.csv` is aggregated from (node index, description, category,
  rows, lookup table if any) — kept for auditing the categorization, not a
  primary deliverable.

## Convention going forward

Any new file or result directory added under `results/` should either be
self-documenting (a script docstring, a CSV header) or get a short note added
to this index — don't leave a new subfolder/file group undocumented.
